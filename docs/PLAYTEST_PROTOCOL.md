# 真机与难度验收

状态：待执行。本文件规定下一步的采样方式，不是已经通过的结论。

## 真机输入

至少分别记录一台iPhone Safari和一台Android Chrome的机型、系统/浏览器版本、屏幕方向和访问地址。在同一份草稿上执行，前后对照房间面积、家具位置和撤销记录：

| 场景 | 必须观察到的结果 |
| --- | --- |
| 房间、擦除、门窗或家具操作中加入第二指 | 取消待提交笔画并进入相机操作，不产生额外图纸修改 |
| 双指后先松一指，剩余指继续移动，再松开 | 只结束相机操作，不落笔；全部抬起后的新单指可以正常操作 |
| 第三指、另一指触碰任务列表或工具按钮 | 不误提交当前图纸，不让任务滚动触点参与地图缩放 |
| 未完成操作时旋屏、切应用、进入后台再返回 | 预览取消，无幽灵笔画；新操作可正常开始 |
| 地址栏展开/收起、横竖屏与安全区变化 | 工具和确认按钮可见；未完成操作不被尺寸变化提交 |
| 抓手移家具、转向、撤销/重做 | 占地、朝向与A/B标记一致，底栏维持单行，抓手物件列表为空 |
| 长任务列表拖左侧滑块及手指滑动 | 两种方式都能到末尾，地图不跟随缩放 |
| 音乐设为0后触屏、旋屏、切后台再回来 | 不重新播放音乐 |

输入验收以物理设备为准；浏览器视口和合成PointerEvent只作为回归辅助。记录失败步骤和前后图纸，不用“没有报错”代替行为判断。

## 人工解题

先以阶段1～11、12～29、30～37、38～45、46～49、50～66、67以后各取样，包含首次教学与后续组合题。最低先收集3位玩家、每阶段至少3次从空白开始且未看参考解的尝试；这是初步采样量，不是统计显著性承诺。

记录：关卡快照版本/指纹、设备、是否首次接触、有效用时、是否放弃、求助次数、求助前后失败提交、主观难度1～5、与前两题的相似感、用途/通路不合理之处。求助会补画参考内容，辅助通过须与无求助通过分开分析。

优先调查：玩家不知道下一步做什么；反复误触或看不见要求；条件全满足却有不合理交通；只是重复同一种排布；新机制或新家具尚未理解就同时引入多个困难。先定位原因，再调整教学、组合、线索或空间预算，不只增加房间数与条目数。

本地自动记录只能提供当前浏览器同源的观察。旧草稿标“中途”，不拿它和完整样本比较通关用时；离线和60秒无输入后的时间不计。主观评价、放弃原因及原生手势失败要人工补记。本地后台只能读取该地址该浏览器的数据，手机/线上记录目前没有远程收集通道。

## 性能与发布

每台目标手机至少收集30次正常领取的出题等待，分别列Worker生成、回退和失败；记录冷启动/已缓存与网络条件。总等待含校验和回退下载，不能把Node计算P95直接当手机结果；生成失败和回退比例一并报告，不能只统计成功Worker样本。

对照相同版本和固定样本检查改动前后表现。输入阻断问题先修；难度权重调整后重新跑`npm test`与`npm run benchmark:quality -- /绝对路径/report.json`，并保留旧题、旧成绩和旧草稿回归。真机与真人结果未收齐前，Q06/Q07/Q14/Q20保持未完成。
